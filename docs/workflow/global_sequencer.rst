.. _global_sequencer:

Global Sequencer Architecture
*******************************

The Global Sequencer is a refactored orchestration system for LSTOSA that separates
data processing into distinct, interdependent stages. Unlike earlier monolithic job
submissions, it uses SLURM dependencies to connect stages and checks the job queue
to avoid duplicate submissions.

.. _sequencer_overview:

Overview
========

The sequencer reads the observation summary of a night and builds a list of
calibration and DATA sequences. For each sequence, it creates the required SLURM
jobs and submits them in the correct order, respecting their data dependencies.

Key principles:

1. **Stage separation:** Each data-processing stage (R0→DL1, Cat-A datacheck, Cat-B/tailcuts,
   DL1→DL1ab, DL1b datacheck) is a separate SLURM job or job array.
2. **Dependency tracking:** Stages are connected with SLURM ``afterok`` dependencies.
3. **Resume capability:** Per-subrun history files track completion and enable
   resuming interrupted processing without rerunning completed stages.
4. **Duplicate avoidance:** Before submission, the sequencer queries ``squeue`` and
   ``sacct`` to detect already-active jobs and avoids resubmitting them.
5. **Dynamic configuration:** Some job scripts are generated at submission time to
   pick up configuration or products created by earlier stages.

.. _job_naming:

Job naming
==========

SLURM job names are constructed per run to enable job tracking and duplicate detection.

**R0 to DL1 array:**

.. code-block:: text

    LST1_<run>

Example: ``LST1_01234``

This is a SLURM array job. The array index corresponds to the subrun number:
``SLURM_ARRAY_TASK_ID=0`` for the first subrun, etc.

**Cat-B calibration and tailcuts pilot:**

.. code-block:: text

    LST1_catB_tailcuts_<run>

Example: ``LST1_catB_tailcuts_01234``

This is a single (non-array) per-run job. It merges Cat-A datachecks, creates
Cat-B calibration, and runs the tailcuts finder when needed.

**DL1 to DL1ab array:**

.. code-block:: text

    LST1_dl1ab_<run>

Example: ``LST1_dl1ab_01234``

Like the R0/DL1 job, this is a SLURM array job with one task per subrun.

.. _job_dependencies:

Job dependencies and submission order
======================================

The sequencer submits jobs in phases, maintaining the required data dependencies:

**Phase 1: Calibration**

If the processing plan requires calibration (e.g., for the first run of the day):

.. code-block:: bash

    sbatch PEDCALIB_script

The PEDCALIB job is a single (non-array) job that produces the daily DRS4
pedestal, charge, and time calibration products.

**Phase 2: R0 to DL1**

After calibration (if it was needed), the R0/DL1 array is submitted:

.. code-block:: bash

    sbatch [--dependency=afterok:PEDCALIB_id] R0_DL1_array_script

This SLURM array job produces DL1a files and per-subrun Cat-A datachecks.

**Phase 3: Cat-B/tailcuts pilot (conditional)**

If Cat-B calibration or a non-standard tailcuts configuration is required:

.. code-block:: bash

    sbatch --dependency=afterok:R0_DL1_id catB_tailcuts_pilot_script

This pilot waits for R0/DL1 to complete, merges Cat-A datachecks, and creates
the required products.

**Phase 4: DL1ab array**

After the pilot completes (or immediately after R0/DL1 if no pilot is needed):

.. code-block:: bash

    sbatch [--dependency=afterok:PILOT_id|R0_DL1_id] DL1AB_array_script

This SLURM array job produces DL1b files using the Cat-B and/or tailcuts products
when applicable.

**Summary dependency graph:**

.. code-block:: text

    With Cat-B/tailcuts:
    PEDCALIB -> R0/DL1 -> Cat-B/tailcuts -> DL1ab

    Without Cat-B/tailcuts:
    PEDCALIB -> R0/DL1 -> DL1ab

    When no calibration needed:
    R0/DL1 -> Cat-B/tailcuts -> DL1ab
    or
    R0/DL1 -> DL1ab

.. _script_generation:

Job script generation
=====================

Job scripts are generated on demand by ``osa.job`` at submission time. This
allows them to encode run-specific information.

**R0/DL1 array script**

Generated by ``osa.job.write_r0_script()``. It contains:

- The R0→DL1 command with calibration files and run information.
- SLURM array specification.
- Environment variable setup (caches, paths).
- Per-subrun history tracking.

**DL1ab array script**

Generated by ``osa.job.write_dl1ab_script()``. It differs from R0/DL1 in that:

- It imports the configuration and option modules at runtime.
- It calls ``get_dl1_prod_id_and_config()`` at runtime to resolve the
  DL1b configuration, which may have been created by the Cat-B/tailcuts
  pilot in the meantime.
- It does not include calibration files (they are already applied).

**Cat-B/tailcuts pilot script**

Generated by ``catb_tailcuts_pipeline.py`` (either standalone or via
``osa.job.write_catb_pilot_script()``). It:

- Waits for all per-subrun Cat-A datachecks to be present.
- Merges them into a single per-run Cat-A datacheck.
- Optionally runs Cat-B calibration.
- Optionally runs the tailcuts finder.
- Creates the ``catB_<run>.closed`` marker on success.

.. _duplicate_avoidance:

Duplicate-job avoidance
=======================

Before submitting any job, the sequencer checks whether a job with the same
name is already queued or running. This is done by:

1. Querying ``squeue`` for active jobs with the target job name.
2. If not found in ``squeue``, querying ``sacct`` for recent jobs with that name
   and checking their state (RUNNING, PENDING, COMPLETING).
3. If found and active, using the existing job ID and not resubmitting.

This prevents job duplication if the sequencer is run multiple times before jobs
finish (e.g., with different dates or due to reruns).

The check is performed by ``osa.job.job_is_active()`` and
``osa.job.get_active_jobid()``.

.. _history_tracking:

History tracking and resume
===========================

Every subrun has a history file recording the completion of each processing step:

.. code-block:: text

    sequence_LST1_01234.0000.history
    sequence_LST1_01234.0001.history
    ...

Each line contains:

.. code-block:: text

    <run_id> <program> <version> <timestamp> <product_id> <metadata> <exit_code>

Example:

.. code-block:: text

    01234 lstchain_data_r0_to_dl1 v0.10.0 2026-09-28 14:30 None all_subruns_finished 0
    01234 lstchain_check_dl1 v0.10.0 2026-09-28 14:35 None cat_a_datacheck 0
    01234 lstchain_dl1ab v0.10.0 2026-09-28 15:00 dl1_prod_id_v2 None 0
    01234 lstchain_check_dl1 v0.10.0 2026-09-28 15:10 dl1_prod_id_v2 None 0

The sequencer uses these histories to determine the resumption level:

- **Level 4:** R0→DL1 pending (no history yet or last entry is a failed r0_to_dl1).
- **Level 3:** Cat-A datacheck pending (r0_to_dl1 succeeded, but check_dl1 for Cat-A
  did not or doesn't exist).
- **Level 2:** DL1ab pending (Cat-A datacheck succeeded, but dl1ab didn't).
- **Level 1:** DL1b datacheck pending (dl1ab succeeded, but the second check_dl1 didn't).
- **Level 0:** Complete (both r0_to_dl1, Cat-A check, dl1ab, and DL1b check succeeded).

The logic is implemented by ``osa.job.historylevel()``, ``osa.job.r0_job_completed()``,
and ``osa.job.run_fully_processed()``.

.. _global_history:

Global run history
==================

In addition to per-subrun histories, the sequencer records global completion
markers in per-run history files:

.. code-block:: text

    LST1_01234.history

This file contains lines added by the sequencer when entire array stages complete.
For example:

.. code-block:: text

    01234 R0_ARRAY v0.10.0 2026-09-28 14:40 None None 0
    01234 DL1AB_ARRAY v0.10.0 2026-09-28 15:15 None None 0
    01234 CATB_CLOSED v0.10.0 2026-09-28 14:50 None None 0

These entries are written by:

- ``osa.job.r0_job_completed()`` when all subruns have a correct r0_to_dl1 + Cat-A
  datacheck sequence in their histories.
- ``osa.job.run_fully_processed()`` when all subruns have a correct dl1ab + DL1b
  datacheck sequence.
- The Cat-B/tailcuts pipeline when it successfully creates the ``catB_<run>.closed``
  marker file.

.. _conditional_processing:

Conditional processing: when is Cat-B/tailcuts needed?
========================================================

The sequencer determines whether to submit the Cat-B/tailcuts pilot using:

.. code-block:: python

    need_catb = (
        cfg.getboolean("lstchain", "apply_catB_calibration")
        and not catB_closed_file_exists(run_id)
    )

    need_tailcuts = (
        not cfg.getboolean("lstchain", "apply_standard_dl1b_config")
        and not tailcuts_json.exists()
    )

    need_pilot = need_catb or need_tailcuts

If ``need_pilot`` is False, the DL1ab job is submitted with a direct dependency
on the R0/DL1 job (no intermediate pilot).

.. _input_state:

Input state and configuration
=============================

The ``--input-state`` option controls which calibration files are provided:

.. code-block:: text

    legacy_raw
        Raw R0 files with no preprocessing. All calibration (DRS4, pedestal,
        charge, time) is applied by lstchain commands.

    gain_selected
        R0 files after gain selection. Calibration is still needed.

    catA_calibrated
        R0 files already calibrated with Cat-A calibration products. The
        sequencer uses these instead of lstchain's default calibration.

This affects both the PEDCALIB decision (whether calibration is needed at all)
and the R0→DL1 command-line arguments.

.. _forced_submission:

Forced submission
=================

The ``--force-submit`` option overrides the normal dependency checks:

- A job is submitted even if no parent job is available (useful during
  development or to recover from transient failures).
- For dl1ab, it will be submitted without the Cat-B/tailcuts pilot even if
  the pilot is needed (though this may cause the job to fail at runtime if
  required files are missing).

This is a debugging tool and should be used with caution in production.

.. _simulation_and_testing:

Simulation and testing
======================

The ``--simulate`` and ``--test`` options are available for validation:

``--simulate``
    Scripts are generated but not submitted. Job commands are logged but not
    executed. File writes that would normally happen are reported as
    ``[SIMULATE]`` instead.

``--test``
    Scripts are generated and executed locally (not via SLURM ``sbatch``).
    Useful for unit testing.

.. _sequencer_output:

Sequencer output
================

The sequencer prints and saves a textual status table in two locations:

1. **``sequencer_table.txt``** in the analysis directory (updated each run).
2. **``log/sequencer_table_<timestamp>.log``** for archival.

The table shows per-sequence status including:

- Job IDs and states.
- Percentages of DL1, Cat-A datacheck, MUON, Cat-B, DL1ab, DL1b datacheck,
  and DL2 files produced.
- CPU time and exit codes.

.. _example_workflow:

Example: full-night processing
===============================

Consider a night with two DATA runs: 01234 (5 subruns) and 01235 (3 subruns),
requiring Cat-B calibration and standard tailcuts.

**Run 1:**

.. code-block:: bash

    sequencer --config osa.cfg --date 2026-09-28 LST1

**Output (simplified):**

.. code-block:: text

    Submitted LST1_01234 (R0/DL1 array, 5 tasks) - job 12345
    Submitted LST1_catB_tailcuts_01234 (pilot, depends on 12345) - job 12346
    Submitted LST1_dl1ab_01234 (DL1ab array, 5 tasks, depends on 12346) - job 12347

    Submitted LST1_01235 (R0/DL1 array, 3 tasks) - job 12348
    Submitted LST1_catB_tailcuts_01235 (pilot, depends on 12348) - job 12349
    Submitted LST1_dl1ab_01235 (DL1ab array, 3 tasks, depends on 12349) - job 12350

**SLURM queue (squeue):**

.. code-block:: text

    12345   LST1_01234          RUNNING   5 tasks
    12348   LST1_01235          RUNNING   3 tasks

**Run 2 (after subruns of 01234 finish, pilot starts):**

.. code-block:: bash

    # No output: 01234 jobs already queued/running
    # 01235 R0/DL1 still running, so pilot for 01235 not yet submitted

    Submitted LST1_catB_tailcuts_01235 (pilot, depends on 12348) - job 12349

**Run 3 (after all R0/DL1 finishes):**

.. code-block:: bash

    # All jobs already queued/running, nothing new to submit

**Run 4 (after pilots finish and DL1ab runs):**

.. code-block:: bash

    # R0/DL1 and pilots complete, DL1ab jobs running
    # Later queries will show DL1ab jobs active

**Finally, when all processing finishes:**

The autocloser merges files, moves them to final locations, and creates
long-term datachecks.

.. _troubleshooting:

Troubleshooting
===============

**Job not submitted:**

Check the sequencer output for reasons like:

- Job already active: ``already queued/running (job X), NOT submitted again``
- No parent job: ``no r0 job available yet``
- Run already complete: ``already fully processed, not submitted``

Query SLURM directly:

.. code-block:: bash

    squeue -n LST1_01234
    sacct -j 12345 --format=JobID,JobName,State

**Job failed:**

Check the job's error log:

.. code-block:: bash

    cat log/LST1_01234_jobid_12345.err

And the subrun history:

.. code-block:: bash

    cat sequence_LST1_01234.0000.history

**Resuming after a failure:**

If a job fails partway through, re-run the sequencer for the same date:

.. code-block:: bash

    sequencer --config osa.cfg --date 2026-09-28 LST1

The sequencer will detect completed subruns and only resubmit incomplete ones.

To force a particular stage to re-run, delete its history entries or use
``--overwrite-catB`` / ``--overwrite-tailcuts`` / ``--force-submit`` as needed.
